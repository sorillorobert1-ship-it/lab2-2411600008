Questions

1. Explain the three components of the MVC architecture (Model, View, Controller) and their roles in your Laravel application. Provide specific examples from your inventory management system for each component.

Model manages data and business rules. In this project the Room model maps to the rooms table, lists fillable fields, and methods such as isLowStock(), isOutOfStock(), and stockValue(). The Reservation model records booking and checkout movements.
View is the user interface. Blade files such as dashboard.blade.php and rooms/index.blade.php display statistics, badges, and forms. They do not write SQL.
Controller handles HTTP requests. RoomController runs index, create, store, show, edit, update, and destroy. DashboardController computes totals and passes them to the dashboard view.

2. In Laboratory Exercise 4, you used JavaScript for client-side interactivity. How does the server-side MVC approach differ from the client-side JavaScript approach? What are the advantages of using a server-side framework like Laravel for business applications?

Lab 4 ran in the browser: charts and counts came from localStorage on one device. Laravel MVC runs on the server: every request is authenticated, validated, and saved in MySQL. Advantages include shared data for many users, hashed passwords, CSRF protection, centralized validation, backups, and business rules that users cannot bypass by editing JavaScript.

3. Describe the flow of an HTTP request in your Laravel application, from the user clicking a button to the response being displayed. Trace this through the routing, Controller, model, and view layers.

Example: staff clicks Save Room on the create form. The browser POSTs to /rooms with a CSRF token. routes/web.php maps that to RoomController@store behind auth middleware. The controller validates input, Room::create() inserts a row, a Reservation may be logged, then Laravel redirects to the room list with a success flash. The index view reads rooms from the model and renders HTML.

4. What is Eloquent ORM, and how did it simplify database interactions? Provide at least two specific examples from your project where you used Eloquent methods.

Eloquent maps tables to PHP classes so we use objects instead of raw SQL for most work. Examples: Room::orderBy('name')->paginate(10) in index(); Room::whereColumn('quantity', '<=', 'reorder_level')->count() on the dashboard; Room::updateOrCreate(['sku' => ...]) in RoomSeeder; $room->reservations() as a hasMany relationship.

5. Explain the purpose of database migrations. How did you use migrations to create your products table? What are the advantages of using migrations over manual SQL table creation?

Migrations version the schema in PHP. 2026_09_15_000001_create_rooms_table.php creates rooms with unique sku, quantity, reorder_level, and nightly rate. 2026_09_15_000002_create_reservations_table.php creates reservation movements with a foreign key to rooms. Advantages: the same schema can be shared on GitHub, rolled back, and applied on any machine with php artisan migrate instead of copying phpMyAdmin SQL.

6. In Laboratory Exercise 4, you used localStorage to store data on the client side. How does storing data in a MySQL database through Laravel differ from using localStorage? What security considerations must you address when handling server-side data?

localStorage is per-browser, unencrypted, and easy to edit. MySQL is centralized, supports relations and concurrent users, and is not visible in DevTools. Server-side we hash passwords, validate and authorize requests, use CSRF tokens, avoid mass-assignment of guarded fields, and never trust the client for prices or quantities without validation.

7. Explain the principle of "Separation of Concerns" in software development. How does Laravel's MVC architecture implement this principle? Provide specific examples from your code.

Separation of concerns means each layer has one job. Validation and redirects live in RoomController, SQL-like queries and isLowStock() live in Room, and HTML/CSS live in Blade and hotel.css. Changing a badge in the view does not require changing the database schema.

8. Compare the approach to building the dashboard in Laboratory Exercise 4 (JavaScript + localStorage) with the approach in Laboratory Exercise 5 (Laravel + MySQL). What are the limitations of the client-side-only approach for real-world business applications?

Lab 4 charts used static or local numbers. Lab 5 charts use DashboardController queries (total rooms, low availability, fully booked, inventory value). Client-only apps cannot be the source of truth for a hotel: data is lost if the browser is cleared, two front-desk PCs do not share bookings, and there is no real audit trail.

9. Discuss the importance of input validation in web applications. How did you implement validation in your Laravel application? What would happen if you did not validate user input before saving to the database?

RoomController uses $request->validate() for required name, unique SKU, numeric quantity and rate, and minimum of zero. Custom messages explain errors on the form. Without validation, duplicate room codes, negative availability, or malformed prices could be stored, and malicious input could break queries or the UI.

10. How did you integrate your chosen color scheme from Laboratory Exercise 4 into your Laravel application? Describe the process of applying custom CSS to override Bootstrap defaults.

The Lab 4 navy-and-gold palette is in public/css/hotel.css as CSS variables (--hotel-primary: #17365d, --hotel-secondary: #2874a6, --hotel-accent: #f4b400). Layouts link this file after Bootstrap. Buttons, navbar gradient, stat-card borders, and focus rings override Bootstrap defaults so login, dashboard, and room pages match.

11. Explain how you connected your dashboard from Laboratory Exercise 4 to the Laravel backend. What changes were necessary to display real data instead of static data?

The visual layout (stat cards, charts, recent list) stayed. JavaScript no longer reads localStorage. The dashboard route is auth-protected. DashboardController@index loads counts from rooms and passes them to Blade. Chart.js receives JSON from those queries. CRUD pages replace simulated add/edit/delete.

12. Discuss the importance of maintaining a consistent visual identity across both the client-side and server-side components of your application. How does this contribute to the user experience?

Staff who used the Lab 4 dashboard still see Robert Hotel branding, the same colors, and similar cards. Consistent identity reduces confusion when moving from mock UI to the real login and room modules, and it looks like one product instead of two unrelated sites.
